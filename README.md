# Project Euler in Piet

**100 mathematical challenges. One esoteric programming language. A different perspective on the art of programming.**

This project explores the first 100 [Project Euler](https://projecteuler.net/) problems through [Piet](https://www.dangermouse.net/esoteric/piet.html), an esoteric programming language in which programs are images rather than conventional source code.

But this is about more than solving mathematical problems.

It is an attempt to express a personal view of the programming world through an unusual artistic medium. Code becomes color. Algorithms become shapes. Logic becomes movement through an image. The constraints of Piet turn computation into something that can be explored both intellectually and visually.

We want to create programs that look like paintings — not just random arrangements of colored pixels that happen to work. Every composition should be an intentional visual creation, where aesthetics and computation coexist. The challenge is to make something beautiful that is also executable.

**This project is developed with AI support.** AI is part of the creative and technical process: helping explore approaches, reason about algorithms, construct Piet programs, and investigate the boundaries of the language. The goal is not to hide that collaboration, but to make it part of the experiment.

## The Idea

Project Euler challenges mathematical reasoning and programming ability.

Piet challenges the way we think about programming itself.

A Piet program is an image composed of colored blocks. Execution depends on transitions between colors, with the direction pointer and color chooser determining the flow of control.

Combining these ideas creates a different kind of programming experience:

**What happens when we take familiar computational problems and express them through a language where the program itself becomes an image?**

Can an algorithm become a painting? Can a visual composition carry both mathematical meaning and executable logic?

The result is both a technical exercise and an artistic interpretation of computation.

## Project Scope

This project is strictly limited to **Project Euler problems 1–100**.

The first 100 problems are the complete scope of this experiment. We will not extend the project to problems beyond 100. The intention is to explore this defined collection deeply rather than turn the repository into an ever-growing archive of solutions.

## Project Goals

- Explore and solve Project Euler problems 1–100 using genuine Piet programs.
- Express algorithms and mathematical ideas through Piet's visual computational model.
- Create Piet programs that resemble intentional paintings rather than arbitrary pixel arrangements.
- Treat program images as both executable code and visual artworks.
- Explore the relationship between logic, mathematics, colors, geometry, composition, and control flow.
- Document the thinking, experimentation, and techniques behind each solution.
- Use AI as an explicit collaborator throughout the exploration.
- Build a Java-based Piet interpreter as a future development target.

The emphasis is not simply on obtaining the correct numerical answers. It is on the process of translating ideas into an entirely different form of computation — without sacrificing visual expression.

## Solutions

Each problem will have its own directory containing, where applicable:

- **Piet program:** The actual executable image.
- **Artwork concept:** The visual idea, composition, or inspiration behind the image.
- **Mathematical approach:** The reasoning behind the solution.
- **Implementation notes:** How the algorithm maps to Piet operations.
- **Expected output:** The result produced by the program.
- **Verification:** Evidence that the program executes and produces the expected result.

Project Euler problem statements will not be reproduced here. Each solution will link to its corresponding original problem.

## Development and Verification

At this stage, Piet programs are verified using the online Piet interpreter:

[https://piet.gulla.net/](https://piet.gulla.net/)

Each completed program should be tested through this interpreter to confirm that it executes and produces the expected result.

A dedicated Java-based Piet interpreter is a future target. It is not a prerequisite for the initial solutions.

## AI-Assisted Exploration

AI is an explicit part of this project.

It assists with mathematical exploration, algorithm design, Piet instruction mapping, visual composition, debugging, and experimentation. The collaboration also provides an opportunity to examine what AI can and cannot do when working within the unusual constraints of an esoteric programming language.

The objective is not merely to have AI generate code. It is to explore ideas together, challenge assumptions, and create something that would be difficult to approach through conventional programming alone.

## Contributions

Contributions are welcome!

Whether you are interested in Piet, mathematical problem-solving, esoteric programming languages, visual computation, or generative art, you are welcome to participate.

Ideas, alternative Piet implementations, visual improvements, bug reports, documentation, and discussions are all appreciated.

A few principles guide contributions:

- **Stay within scope:** Only Project Euler problems 1–100 are included.
- **Keep it genuine:** Solutions must be actual Piet programs.
- **Make it beautiful:** Aim for intentional visual compositions, not random pixel arrangements that merely execute.
- **Make it work:** Every completed program must be verified using the designated Piet interpreter.
- **Be transparent:** Acknowledge AI assistance where applicable.

Feel free to open an issue or submit a pull request.

## Design Principles

1. **Authenticity:** Every solution must be a genuine Piet program, not a conventional-language implementation disguised as one.
2. **Correctness:** A solution is not complete until its Piet program has been executed and verified.
3. **Artistic expression:** Each program should be designed as a visual composition, with deliberate attention to color, geometry, balance, and aesthetics.
4. **Beauty with purpose:** The image should be more than decoration. Its visual structure should coexist with, and ideally reflect, its computational logic.
5. **Transparency:** AI assistance is acknowledged as part of the development process.
6. **Exploration:** Unusual approaches and unexpected discoveries are welcome.
7. **Understanding:** The reasoning behind a solution matters as much as its final output.
